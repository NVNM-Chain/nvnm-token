## Methodology

Read this before quoting any number.

Call measurements come from `vm.snapshotGasLastCall`, which records the gas consumed
inside the measured call frame, independent of the test code around it. Deployment
measurements are `vm.startSnapshotGas` / `vm.stopSnapshotGas` windows around contract
creation, each the only window in its test: a later window in the same test would also
count the test’s own gas since the previous window closed.

**Included:** execution and storage costs of the call.

**Excluded:** the 21,000 gas intrinsic transaction cost; calldata cost (16 gas per
non-zero byte, 4 per zero byte — roughly 400–600 gas for a `transfer`); the caller’s
cost of making the call, including its access to the token account; and refunds,
which settle at the end of a real transaction and are capped at a fifth of gas used.

**Transfer warm-up.** Transfer scenarios perform a zero-value transfer between the
same parties before measuring. This touches both balance slots without changing
balances.
Approval and transferFrom cases have their own allowance access/transition setup;
they should not be treated as uniformly warm storage benchmarks.

Adding 21,000 and calldata to these rows does not reproduce a wallet transaction.
Use receipt-based benchmarks before publishing standalone wallet-transaction costs.

**Gas schedule.** Every figure is measured under the gas rules of the EVM version
above. A network that has activated a later fork charges what its own rules say, and
the difference can be large: after the fork Sepolia activated on 6 October 2026,
deploying the token there takes about seven times the gas these rules give. Call
costs can change as well. Take gas limits for real transactions from the target
network’s node (`eth_estimateGas`), as the Makefile’s deploy targets do.

## First vs repeat transfer in one transaction

This delta is **not** a pure EIP-2929 cold-access figure, and should not be quoted as
one. It combines cold storage-slot access
with EIP-2200 dirty-slot pricing: the repeat transfer rewrites slots already modified
in the same transaction, at 100 gas each instead of 2,900. The common transfer row
uses its own zero-transfer warm-up; approval and allowance rows have different setups.
